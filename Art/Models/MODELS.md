# The Twelfth Stamp: model list

Generated by `Tools/blender/write_models_md.py` from the build and re-import logs in `Art/Models/_logs/` (last run 2026-10-18). Every model is built by a Python script in `Tools/blender/`; run it headless with `blender -b --factory-startup --python Tools/blender/<script>.py` to rebuild.

## Conventions (all files)

- Output: `Game/Assets/Resources/Models/<Name>.fbx`, one asset per file. Units are metres at real-world scale. The FBX stores UnitScaleFactor 100 (1 unit = 1 m), so Unity imports at scale 1.
- Export call: `export_scene.fbx(use_selection=True, apply_unit_scale=True, apply_scale_options='FBX_SCALE_ALL', axis_forward='-Z', axis_up='Y', bake_space_transform=True, object_types={'MESH','EMPTY'}, mesh_smooth_type='FACE', use_tspace=True, add_leaf_bones=False, bake_anim=False)`.
- Orientation: assets are built with their front facing Blender -Y and up +Z. In the exported FBX that front is +Z (verified by parsing the raw file). Unity mirrors X on import, so **the front faces Unity local +Z (transform.forward)**, up is +Y, and Blender +X becomes Unity -X. The "Front" column gives each file's front axis.
- Hierarchy: each file has one root empty named after the file. Every mesh is a child of that root. Rotation and scale are applied on every object (identity), and child locations are the pivots listed below.
- Materials: slots are named from the TS_* list. Base colours are preview values only; the game assigns its own materials by slot name. All meshes have UVs: smart-project by default, with explicit 0..1 UVs where noted. Meshes have custom (weighted) normals and are triangulated where they had n-gons.

## Notes

- Left/right naming follows the wearer or user (for example, LensL is the wearer's left lens). In Blender the wearer's left is +X; in Unity it is -X, which is the wearer's left when facing +Z.
- Preview PNGs are Eevee renders (800x600, neutral grey, three-quarter view). Extra QA views use suffixes such as _front, _side and _back.
- Hierarchy rule: with bake_space_transform=True the Blender FBX exporter writes a spurious 90-degree rotation on grandchildren (checked in the raw FBX), so every file keeps all meshes as direct children of the root. The export helper refuses deeper nesting.
- No third-party or downloaded assets are used. Every model is original geometry built by the scripts in Tools/blender. Nothing was taken from Poly Haven (the scripted models fit the size and slot contract exactly), so there was nothing to add to Art/AssetLedger.md.
- Working .blend files for every asset are saved in Art/Models/_blend/ (about 16 MB, compressed). The QA helpers closeup.py and uvcheck.py use them. They can be regenerated from the scripts, so they can be gitignored if size matters.
